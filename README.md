# Customer CRUD API Practice

A Spring Boot practice project for managing customers with basic CRUD APIs.

## Features

- Create customer
- List customers
- Get customer by id
- Update customer
- Delete customer
- Validate request data
- Return consistent error responses
- Run with Docker Compose and MySQL

## Tech Stack

- Java 21
- Spring Boot
- Spring Web MVC
- Spring Data JPA
- MySQL
- Flyway
- Docker
- Maven

## Requirements

- Java 21
- Docker Desktop
- Maven Wrapper included in this project

## Run with Docker Compose

Build the application jar:

```powershell
.\mvnw.cmd package
```

Build the Docker image:

```powershell
docker build -t customer-crud-api-practice:1.0.0 .
```

Start the application and MySQL:

```powershell
docker compose up -d
```

Check containers:

```powershell
docker ps
```

API base URL:

```text
http://localhost:8080
```

Stop containers:

```powershell
docker compose down
```

## Run Locally with IntelliJ

Start MySQL only:

```powershell
docker compose up -d mysql
```

Run the Spring Boot application from IntelliJ, or run:

```powershell
.\mvnw.cmd spring-boot:run
```

The local application uses MySQL at:

```text
localhost:3307
```

## API Endpoints

| Method | Path | Description |
| --- | --- | --- |
| POST | `/api/v1/customers` | Create customer |
| GET | `/api/v1/customers` | List customers |
| GET | `/api/v1/customers/{id}` | Get customer by id |
| PUT | `/api/v1/customers/{id}` | Update customer |
| DELETE | `/api/v1/customers/{id}` | Delete customer |

## Customer Fields

| Field | Type | Rule |
| --- | --- | --- |
| id | BIGINT | Primary key, auto increment |
| name | VARCHAR(100) | Required |
| email | VARCHAR(255) | Required, unique, valid email format |
| phone | VARCHAR(30) | Optional |
| createdAt | DATETIME | Generated by application before insert |
| updatedAt | DATETIME | Generated by application before insert/update |

## Create Customer Example

Request:

```json
{
  "name": "Alice",
  "email": "alice@example.com",
  "phone": "0912345678"
}
```

Response:

```json
{
  "id": 1,
  "name": "Alice",
  "email": "alice@example.com",
  "phone": "0912345678",
  "createdAt": "2026-09-17T00:47:04",
  "updatedAt": "2026-09-17T00:47:04"
}
```

## Update Customer Example

Request:

```json
{
  "name": "Alice Wang",
  "email": "alice@example.com",
  "phone": "0987654321"
}
```

Response:

```json
{
  "id": 1,
  "name": "Alice Wang",
  "email": "alice@example.com",
  "phone": "0987654321",
  "createdAt": "2026-09-17T00:47:04",
  "updatedAt": "2026-09-17T00:51:35"
}
```

## Error Response Format

```json
{
  "code": "CUSTOMER_NOT_FOUND",
  "message": "Customer not found with id: 1",
  "details": [],
  "timestamp": "2026-09-17T00:52:54"
}
```

Common status codes:

| Status | Meaning |
| --- | --- |
| 201 | Created |
| 200 | OK |
| 204 | No Content |
| 400 | Validation error |
| 404 | Customer not found |
| 409 | Duplicate customer email |

## Notes

- Flyway manages database schema creation.
- JPA validates that the Entity mapping matches the database schema.
- The API does not expose Entity objects directly. It uses request and response DTOs.
- MySQL data is stored in the Docker volume `mysql_data`.
